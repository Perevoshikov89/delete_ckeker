# 3.2 Regression Checker

Read-only утилита для регрессионной проверки обработки события FL_Event_3.2.

## Назначение

Выявление ошибок, при которых обработка события 3.2 удаляет записи не только указанного *TARGET UID* (ACC_SERIAL_NUM), но и данные других договоров того же субъекта.

Основная задача — подтвердить, что:

- количество удалений в БД соответствует loader log;
- удаление произошло только для TARGET UID;
- количество записей в таблицах блоков 2-го уровня для всех ACC_SERIAL_NUM, отличных от TARGET UID, не должно измениться;
- отсутствие любых изменений количества записей для других ACC_SERIAL_NUM.

## Принцип работы

Утилита сравнивает два состояния БД:

```text
BEFORE → обработка события 3.2 → AFTER

Дополнительно анализируется сообщение loader.

Проверка выполняется в несколько этапов:

BEFORE + AFTER + Loader log
            ↓
      3.2 Regression Checker
            ↓
   ┌────────────────────────┐
   │ Loader ↔ DB             │
   │ Target UID              │
   │ Target UID + reported_dt│
   │ Control UID             │
   │ Unexpected increase     │
   └────────────┬───────────┘
                ↓
            PASS / FAIL

Перед запуском:

1. Подготовьте загружаемые файлы:
Файл 1. с двумя сделками (А и Б) субъекта с разницей в открытии (например, неделя)
Файл 2. с событием 3.2 с указанием startDate меньше даты события сделки сделки Б 
2. Загрузите файл 1 и запишите значение поля ACC_SERIAL_NUM удаляемой в последующем сделки

После запуска:

Укажите параметры подключения к DB2.
Введите FID тестового субъекта.
Снимите BEFORE baseline и сохраните (json)
Выполните событие 3.2 (загрузите файл 2)
Получите соответствующее сообщение loader'a об удалении
Снимите AFTER baseline и сохраните (json)
Вставьте сообщение loader'a в checker.
Укажите TARGET UID (ACC_SERIAL_NUM), если он не определился автоматически.
Нажмите «ПРОВЕРИТЬ EVENT 3.2».
